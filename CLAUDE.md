# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

Tex is a personal desktop assistant: universal search (files, folders, installed apps) plus clipboard history. Implemented: tray icon, global hotkeys, popup, file/folder/app search (service + results UI), the clipboard history (capture of text and images, encrypted storage, retention, the history window opened by Alt+V), the settings window (General, Search and Clipboard tabs), the first-run onboarding (`Local/specs/2026-10-17-onboarding-design.md`) and automatic updates (`Local/specs/2026-10-17-atualizacao-design.md`) and the text reader (Shift+Enter in the popup; `Local/specs/2026-10-18-leitor-design.md`). The clipboard design is in `Local/specs/2026-10-16-clipboard-design.md`.

The full functional requirements document (in Portuguese) is `Local/Tex_Documento_Requisitos_Funcionais.md`. `README.md` is the public English summary of it. Design specs live in `Local/specs/`.

## Commands

```sh
cargo run -p tex-app                     # debug build, keeps a console for eprintln!
cargo run -p tex-app -- --read <file>   # debug builds: open a file in the reader at start
TEX_EXTENSIONS_DIR=<folder> cargo run -p tex-app -- --read <file>   # debug builds: read reader extensions from <folder> instead of %APPDATA%\Tex\extensions; put a folder with an extension.toml in it (format in README) and use the Tools menu
cargo build --release                    # target/release/tex.exe, no console window
cargo test                               # all tests
cargo test -p tex-app popup_origin       # tests matching a name
cargo test --release -p tex-index --test performance -- --ignored --nocapture   # 3M-entry search benchmark
cargo clippy --all-targets
cargo fmt
cargo run -p tex-indexer -- console        # admin terminal: index and serve in the foreground
cargo run -p tex-indexer -- install        # admin terminal: register and start the service from this exe
cargo run -p tex-indexer -- install --all-users   # admin terminal: same, but every signed-in user may search
cargo run -p tex-indexer -- uninstall      # admin terminal: stop and remove the service
"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" /DAppVersion=0.4.3 installer\tex.iss   # run from PowerShell (Git Bash rewrites /DAppVersion); after cargo build --release; AppVersion = workspace version; output target\installer\Tex-Setup-0.4.3.exe
cargo run -p tex-app --example update_key -- C:\outside\repo\update.key   # once: makes update.pub and writes the private key to the file; put it in the TEX_UPDATE_KEY secret
cargo run --release -p tex-app --example sign_update -- target\installer\Tex-Setup-0.4.3.exe 0.4.3   # TEX_UPDATE_KEY (hex) in the environment; writes the .sig beside the installer
cargo run --release -p tex-indexer --example fake_server -- C:\some\folder   # no admin: serve one folder for app testing
```

Only one Tex can run at a time (named mutex). Quit the running one from the tray menu before starting another, or the new one exits immediately.

## Architecture

Cargo workspace, crates in `crates/`:

- `tex-app` (binary `tex`): Slint UI and app wiring. `.slint` files are in `ui/` and compiled by `build.rs` with the Fluent style. `ui/app.slint` re-exports the six root components: `Popup` (frameless search window), `HistoryWindow` (frameless clipboard history, `ui/history.slint`), `AboutWindow`, `SettingsWindow` (General, Search and Clipboard tabs), `OnboardingWindow` (first-run wizard, `ui/onboarding.slint`), and `TexTray` (Slint's built-in `SystemTrayIcon`, so there is no `tray-icon` crate; its menu also opens the history and pauses capture). Visual identity ("v3 Mascote"): `ui/theme.slint` (`Tokens`), `ui/artwork.slint` and `ui/kit/` (own components that only read `Tokens`; the Fluent widgets remain only in the About window because of `AboutSlint`, and the reader's `ListView`, kept for its virtualization; its scrollbar follows `Palette.color-scheme`); Nunito and IBM Plex Mono fonts embedded (OFL) and Phosphor icons (MIT) in `ui/icons`. `theme.rs` holds the modular designs: a new design is a `Design` value in `DESIGNS`, and no `.slint` outside the theme files uses a literal color (`tests/tokens.rs` enforces it). The popups are cut with `shape_tabbed_window`; the settings and reader windows are frameless (`drag_window`, `drag_resize_window`, `round_corners`), wired by the `frame::wire_frame!` macro, which keeps each window's own title double-click time. The executable icon is `assets/tex.ico`, embedded by `build.rs` (`embed-resource`); `assets/make_assets.py` regenerates the icon and illustrations from the design handoff. search_client.rs owns the pipe on a background thread and coalesces keystrokes (only the newest search is sent), and the popup drops `Results` whose id is not the newest search sent; results.rs holds the pure row/selection logic. icons.rs loads real app icons on a COM thread (tex_platform::app_icon) into a 256-entry cache that lives on the UI thread; rows show the plain icon until the real one arrives. settings.rs is the pure settings model (`%APPDATA%\Tex\settings.toml`, read field by field so bad values fall back to defaults; an unparsable file is renamed to `.bad`); shortcut.rs converts shortcuts between text, Slint key events and `global-hotkey`. app.rs holds the UI-thread `AppState` (settings, the two registered hotkeys, Windows-key hook, when the popup closed, the window to paste into) in a thread-local; changes apply immediately and are saved on every edit. The Tex and history shortcuts can never be the same, and both are unregistered while either one is being recorded. clipboard_client.rs runs a worker thread that owns the `tex_clipboard::Store` (`%LOCALAPPDATA%\Tex\clipboard.db`, key in `clipboard.key` protected by DPAPI; a key that is missing or does not open the database moves both to `.bad` and starts empty): the UI sends `Command`s and gets `Event`s back through `invoke_from_event_loop`, never touching the database. The worker coalesces searches, applies retention, and waits on its channel with `recv_timeout` until the next expiry (plain `recv` when nothing can expire). history.rs holds the pure history rows, selection, sizes and dates; the history window drops its rows when hidden. update.rs is pure: it reads the GitHub release JSON, compares versions and verifies the ed25519 signature over `tex-setup\0<version>\0<sha256 hex>` against the public key embedded from `update.pub` (32 raw bytes; `examples/update_key.rs <file>` made it and writes the private key to that file outside the repository instead of printing it; `examples/sign_update.rs` signs in the release workflow with the `TEX_UPDATE_KEY` secret). update_client.rs runs a worker thread (a generic `Checker` over the download function, so the flow is tested without network) that checks at start, after the onboarding and when the popup opens more than 24 h after the last check (no timer), downloads to `%LOCALAPPDATA%\Tex\updates`, and on "Update and restart" reopens the installer with `open_locked`, verifies again and runs it unelevated with `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE`, holding the handle until it exits: Inno Setup asks for UAC, its `PrepareToInstall` kills Tex, and `ExecAsOriginalUser` reopens it. The UI sets `Installing` at once; if the installer exits while Tex is still running, nothing was installed and the state goes back to ready. Invalid release JSON is `Failed` and keeps the downloads. Debug builds read `TEX_UPDATE_REPO` (`owner/repo`) to test against another repository. onboarding.rs is the pure onboarding model (step 0–10, answers as option indexes where 0 is always the factory default and `None` keeps the current value, `apply`). The wizard opens at start while `general.onboarding_done` is false, which includes upgrades from before it existed; until it is done nothing is captured (`app::client_settings`) and the Windows-key hook stays off (`Settings::winkey_active`). Choosing the theme previews it (`AppState::theme_preview`), and the answers apply through `apply_settings`, the same path as the settings window. "Redo" in Settings › General (`redo_onboarding`) hides the settings and reopens the wizard in upgrade mode while `onboarding_done` stays true, so nothing is gated again. Started with `--autostart` (the installer's `Run` value) and "Start with Windows" off, the app exits before creating windows. All visible text uses `@tr`; `ui/translations/pt_BR/LC_MESSAGES/tex-app.po` is bundled by `build.rs` (no translation context), so add every new string there. Rust passes data (categories, drive letters, numbers) and Slint builds the sentences. `reader.rs` is pure (page cache, link targets, window size, line cuts, Markdown block rows) and `reader_client/` (`mod.rs`: registry, loads and wiring; `edit.rs`, `search.rs`, `model.rs`) owns the open reader windows (`ReaderWindow` in `ui/reader.slint`): one window per file, one worker thread per window that probes, loads and serves pages of lines to a paginated `LinesModel`, answers coming back through `invoke_from_event_loop`; Shift+Enter in the popup opens it (`ResultRow.readable`), links open through `open_path`, and debug builds take `--read <file>`. Ctrl+E edits with the kit's `Editor`; `EDIT_LIMIT` only gates entering edit mode, so an edit that grew past it can still be reopened and saved; Ctrl+S goes through `save_check` (a change made outside or lost characters ask in the banner) and saves with `replace_file`, does not rewrite a clean document whose file is unchanged (`needs_write`), and an outside version is written over only after the banner asked about that very version (`Reader::acknowledged`, set when the save or the focus check shows the conflict) and "Overwrite" or "Save anyway" confirms it (`changed_outside`), so a newer outside version asks again; Ctrl+S on a clean document of an unchanged file does nothing (`SaveOutcome::Unchanged`); when the window gets the focus the `Stamp` is compared (`outside_change`: reloads by itself without changes, a conflict banner with changes, not shown again for the version already asked about, whose Reload asks before discarding them, a deleted banner); loads carry a generation number so a reload ignores old events; Ctrl+F searches with `fold` on a cancellable thread (a new query, a reload or closing the bar or window cancels it), up to `MAX_HITS` results, and the jump to a hit is in two steps (`jump-target`); closing with changes asks to save, discard or cancel. Inside `BlockView` (itself a `VerticalLayout`), a wrapped `StyledText` or `Text` nested in a second layout (a `HorizontalLayout`, or a `VerticalLayout` with padding) reported a wrong height, so list items, quotes and code boxes put the text in a `Rectangle` whose `height` is the text's `preferred-height`, with an explicit `x` and `width`, and table cells get explicit widths. The plain-text rows of the `ListView` use the same pattern for consistency (a one-level `HorizontalLayout` row did render correctly there), with the row `width` bound to the list's `content-width` so unwrapped lines scroll sideways. Reader extensions (format in README): `settings::extensions_dir()` (`%APPDATA%\Tex\extensions`; debug builds read `TEX_EXTENSIONS_DIR`) is read into a `Catalog` at start (so `results::readable` also takes the viewers' types for the popup's Shift+Enter), again on every `reader_client::open` and every time the Tools menu opens; no watcher. A `Viewer(ext)` file runs its viewer in the window's worker (the raw text is loaded beside it when it is text up to `TEXT_LIMIT`, so Ctrl+E edits the raw file; saving outside edit mode or leaving edit mode after a save runs the viewer again through `reload`). tools.rs is pure: `resolve` gives each tool its shortcut through `shortcut.rs`, refusing `READER_KEYS`, keys an earlier tool took, and Ctrl+Alt with anything but a letter or an F key (AltGr arrives as Ctrl+Alt); `note` says why a tool is off or lost its shortcut and `describe` turns a `RunError` into a `Reason`, both as int codes that `reader.slint` turns into `@tr` sentences (`run-reason`). `reader_client/extensions.rs` builds the Tools menu (tools of the file's type, broken manifests, viewer conflicts, "Open extensions folder"), runs one tool at a time on a thread with a run id (a reload or closing the window cancels it and its result is ignored; the "Running…" banner has Cancel) and applies the output: `replace` puts it in place of the document or the selection (refused if the text changed meanwhile), `show` keeps it in `Reader::output` and shows it in the output panel (30% of the window) as unwrapped lines in a `ListView`, like text mode, and Copy copies the kept text, `none` shows the "done" toast.
- `tex-platform`: OS-specific code behind a per-OS module with the same public API (`SingleInstance`, `work_area_under_cursor`, `primary_work_area`, `open_path`, `reveal_in_folder`, `app_icon`, `pick_folder`, `pick_file`, `user_language`, `system_uses_dark_theme`, `local_time`, `WinKeyHook`, `catch_windows_key`, `ClipboardWatcher`, `write_text`, `write_image`, `foreground_window`, `take_foreground`, `restore_foreground`, `lock_foreground`, `paste_into`, `shape_tabbed_window`, `round_corners`, `protect`, `unprotect`, `http_get`, `open_locked`, `replace_file`). `WinKeyHook` is a low-level keyboard hook on its own thread: it swallows the Windows key until another key makes it a combination (then it sends the key-down first), and a lone press calls back. Windows does not call that hook while a window of Tex has the focus, so the popup's window procedure is subclassed (`catch_windows_key`): it sends the mask key VK 0xE8 on the Windows key-down and closes the popup on the lone release. The popup takes the foreground with `take_foreground` (never winit's `focus_window`, whose injected Alt makes Windows open the Start menu), locks it while open so the Start/Search window cannot steal it, and on close gives it back to the window that had it (`restore_foreground`) instead of letting Windows activate the Search window. `ClipboardWatcher` is a message-only window on its own thread (`AddClipboardFormatListener`) that reads each update into a `Clip`: text or DIB, the opt-out formats, the owner exe name, and whether Tex wrote it. It first reads only the formats (`ClipFormats`) and asks a callback which `Payload` to read, so skipped copies (paused, opted out, ignored apps) read no content and the DIB is read only when the image is the one captured; the app answers with `ClipboardClient::wanted`, which applies the capture rules to the settings `configure` last set. Windows can queue several `WM_CLIPBOARDUPDATE` for one clipboard state, so an update whose `GetClipboardSequenceNumber` matches the last one is not read. Tex's own writes carry the `Tex.Copy` format so they are not captured again; `paste_into` gives the focus back and sends Ctrl+V with `SendInput`. `protect`/`unprotect` are DPAPI for the current user. `http_get` is WinHTTP (HTTPS only, system proxy, follows redirects, body size limit); `open_locked` opens a file refusing writers and deletes, so the installer cannot be swapped between its signature check and its launch. `replace_file` writes a temporary file beside the target and swaps it in with `ReplaceFileW` (`MoveFileExW` when the target is gone); the temporary file is deleted on error. The hook, the watcher, clipboard writes and paste are only verified manually. Uses `windows-sys` 0.59, the same version `global-hotkey` pulls in.
- `tex-clipboard`: the clipboard history, pure and tested (no OS calls; the key comes from outside). `crypto.rs` seals fields with XChaCha20-Poly1305 (`nonce || ciphertext`). `image.rs` converts DIB ↔ RGBA ↔ PNG and makes thumbnails. `store.rs` is the SQLite database (`rusqlite` bundled, WAL, `auto_vacuum = INCREMENTAL`, schema in `user_version`): one row per copy with `kind`, `copied_at`, `size` and `favorite` in clear and `name`, `summary` and `content` sealed; a check row in `meta` detects a wrong key, and a row that does not decrypt shows as unreadable and can only be deleted. Search folds with `tex_index::fold`, keeps the filter in the `WHERE`, matches images only by name, and can be cancelled. `retention.rs` holds the pure rules (time; storage from 90% down to 80%; favorites never removed nor counted) and `capture.rs` decides whether a copy is saved, in the spec's order, and fingerprints content to recognize the same copy written again (`is_repeat`).
- `tex-reader`: the core of the text reader, pure and tested (`std`, `pulldown-cmark`, `serde` + `toml`, and `windows-sys` / `libc` only for `runner.rs`); its window is `ui/reader.slint` in `tex-app` (`Local/specs/2026-10-18-leitor-design.md`). `kind.rs` picks how a path opens (`Markdown`, `Plain { wrap }`, `Viewer(ext)` for extension viewers, which win over the core list, or `Unknown` without an extension, decided by `sniff`: a NUL byte without a BOM is binary). `encoding.rs` decodes UTF-8 (BOM or not), UTF-16 LE/BE (BOM) and Windows-1252 (when not valid UTF-8; table written by hand), turns breaks into `\n`, and `encode` writes back with the same encoding, BOM and line ending (`fits` tells whether Windows-1252 loses characters). `detect` accepts a UTF-8 character cut at the end (it also reads 64 KB heads); `decode` of a whole file does not, and reports `lossless: false` when a BOM'd file had invalid bytes. `markdown.rs` turns Markdown into `Block`s whose `inline` is the subset `slint::StyledText::from_markdown` renders, other ASCII punctuation escaped. `lines.rs` indexes large files with a checkpoint every 64 lines and reads a page at a time from the `BufRead` buffer (lines cut at 64 KB without splitting a character, the rest skipped in bulk). `document.rs`: `probe` reads the first 64 KB; `Probe::load` opens the file once, stamps it from that handle and reads up to `TEXT_LIMIT` (2 MB) as text, indexing larger files (or ones that grew since the probe) read-only; only text up to `EDIT_LIMIT` (128 KB) is editable, because Slint's `TextInput` lays out the whole text on every key (measured: 512 KB already lags); `Document::fits` (false when Windows-1252 would lose characters or the decode was lossy) must be checked before saving; `Stamp` (mtime + length) detects changes made outside. `extensions.rs` reads `<folder>/extension.toml` manifests into a `Catalog` (folders in alphabetical order; a bad manifest, a `command` part that is absolute or has `..`, or `"*"` in a viewer is a `Broken` entry), answers `tools_for`, `viewer_for` (the first folder wins a type; the others are `viewer_conflicts`) and builds the `Job` (`command[0]` and later parts that are files in the extension folder become absolute, cwd the folder, `TEX_FILE`, `TEX_EXTENSION_DIR`, `TEX_VERSION`). `runner.rs` runs a `Job` with `std::process` (no console window), `LIMITS` 10 s and 16 MB of stdout, and `Cancel`: threads write stdin, read stdout (refused above the limit), read stderr to the end keeping 64 KB, and wait for the exit, all reporting on one channel that the caller's thread waits on with `recv_timeout` until stdout, stderr and the status are in, so a timeout or a cancel also catches a process that closed its outputs; the process tree goes in a job object on Windows (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` while it runs, cleared when it ends normally, so what it started may outlive it) or its own process group on Unix, and a cancel, timeout or too much output ends the whole tree (`TerminateJobObject`, `kill(-pgid)`). Its tests spawn `powershell`/`cmd` on Windows and `sh` on Linux, and take about 10 s.
- `tex-index`: pure in-memory file name index (no OS calls). One `VolumeIndex` per drive: a `Vec` of 12-byte entries positioned by MFT record number, plus a single UTF-8 name buffer. Renames append names; the buffer is compacted when over 25% is garbage. `search` scans all volumes in parallel (`std::thread::scope`, top-K heap per thread) and can be cancelled. Queries split on `/` and `\`: the last piece is the name and earlier pieces are folders that must match ancestors in order, nearest first, through a per-search byte table of matching directories (a leading `C:` picks the drive); a name term starting with `.` must end the name. Snapshots are a versioned binary format; bump `VERSION` in `snapshot.rs` on any layout change. Queries carry `app_roots` (Start Menu folders, built by the service from `%ProgramData%` and the request's home); shortcuts below them ignore hidden ancestors, and apps rank above everything else. Hidden and system are separate filters (the Windows folder and root metadata count as system), and queries also carry excluded folders and which categories to return; both are applied before a hit takes a slot in the limit.
- `tex-ipc`: messages between the app and the search service (`serde` + `postcard`, u32 length prefix, 4 MB limit).
- `tex-indexer` (lib + binary): the search service. Each NTFS volume gets a thread (`runner.rs`) that loads its snapshot from `%ProgramData%\Tex\index` or enumerates the MFT (`FSCTL_ENUM_USN_DATA`), then blocks on `FSCTL_READ_USN_JOURNAL` and applies close records. `engine.rs` answers requests and is pure (tested); `pipe.rs` serves `\\.\pipe\tex-indexer` with a DACL for SYSTEM, Administrators and either the installing user (`--allow <sid>`) or every interactive user (`--allow-interactive`, from `install --all-users`). The pipe is strictly request→response: never read and write the same synchronous pipe handle from two threads. New volumes are discovered at start and on every `Status` request (no device notifications). Opening volumes needs admin, so `runner.rs` and `volumes.rs` I/O are only verified manually. The SCM starts the exe as `tex-indexer service --allow…` (`service.rs`); that subcommand is not for manual use. Data lives in `%ProgramData%\Tex` (private ACL): snapshots in `index\<volume serial>.bin`, written via temp file + rename, and the log in `logs\indexer.log`, rotated at 1 MB. Check the log first when the service misbehaves.

Releases: `installer/tex.iss` (Inno Setup, UTF-8 with BOM) installs both exes to Program Files. Before copying it removes any existing `tex-indexer` service using the new exe extracted to `{tmp}`, then runs `install` or `install --all-users` according to its "Who can use Tex" page and puts the shortcut and the `Run` value in the user or the common scope. With `/UPDATE` (passed by the app's updater) it reopens Tex at the end with `ExecAsOriginalUser`. `.github/workflows/release.yml` runs `cargo test`, then builds the installer, signs it (`sign_update`, secret `TEX_UPDATE_KEY`; a release without the secret fails) and creates a draft GitHub Release with `Tex-Setup-<version>.exe` and `Tex-Setup-<version>.exe.sig` on every `v*` tag, which must match the workspace version. Losing the private key means installed copies can no longer update. There is no other CI, so run `cargo test`, `cargo clippy --all-targets` and `cargo fmt` locally before committing.

Event flow: everything runs on the main thread inside Slint's winit event loop (`run_event_loop_until_quit`, so hiding every window does not exit). `global-hotkey` needs a Win32 message loop on the thread that created the manager, and winit's loop provides it. Hotkey callbacks arrive through `set_event_handler` and go back into Slint with `invoke_from_event_loop`; the history hotkey is told apart by its id. Nothing polls and there are no timers, so the CPU stays at 0 while idle. Keep it that way.

Slint uses the software renderer (`renderer-software`) with winit. Access to the raw winit window (focus, skip taskbar, focus-lost events) goes through the `unstable-winit-030` feature, which is tied to Slint's minor version. Recheck it when upgrading Slint.

## Stack

- Rust for everything: UI and features, built as one native desktop program. The UI framework is Slint, chosen for its low RAM and CPU footprint. Target: under ~80 MB of RAM at idle with the popup closed.
- Windows first, with macOS and Linux planned later. Keep OS-specific code (clipboard, file index, installed apps, global hotkey, tray) in `tex-platform`'s per-OS modules, all exposing the same public API, so other platforms can be added without touching the UI or the core.
- The UI is a frameless popup opened by a global hotkey (Spotlight/PowerToys Run style). It lives in the system tray the rest of the time.

## Domain invariants

The implementation should hold to these rules from the spec:

- **Search** covers every disk available to the user plus installed apps, in one query. Results are grouped by category (files, folders, apps), filterable, and show the location for files and folders. It must feel instant, so use a local index that stays up to date instead of scanning disks on each query.
- **One copy = one row.** Every copy event creates a new history entry, even when the content is identical. Never deduplicate. The one exception, decided by the user: apps often write a single copy more than once (OLE writes and then flushes; some tools write twice), so content identical to the last saved row within 1 s (`REPEAT_WINDOW_MS`) is that same copy and is not saved again. Entries are fully independent: rename, edit, favorite, delete, and expiry act on one row only.
- **v1 content types** are text and images. Text supports search by content and editing. Images support preview, rename, favorite, and copy back when the format is supported. Large files, folders, and ZIPs are out of scope for v1.
- **Retention** follows one user-chosen policy:
  - By time: non-favorites expire after 3 days, 1 week, or 1 month.
  - By storage: at 90% of the configured limit, remove the oldest non-favorites until there is real headroom, not one entry at a time.
  - Each row therefore needs a copy timestamp, its size in bytes, and a favorite flag. Retention runs in the background, without the UI being open.
- **Favorites** are never removed by time or storage cleanup. Only the user deletes them.

Decided by the user (details in `Local/specs/2026-10-16-configuracoes-design.md` and `Local/specs/2026-10-16-clipboard-design.md`):

- Storage limits are fixed presets (250 MB, 500 MB, 1 GB, 2 GB, 5 GB), never a typed value.
- Favorites do not count toward the storage limit, so they are never limited.
- Sensitive content is the user's call: Tex does not detect passwords. It offers pause, ignored apps, respecting the clipboard formats other apps use to opt out, and deleting entries.
- Images can only be renamed; their content is not editable.
- Tex's own copies back to the clipboard are not captured.
